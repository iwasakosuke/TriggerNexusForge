# 11_TNF_CORE_PROMPTS — 中核プロンプト集

<!-- TNFのDNA(その2)。全AI社員・全業務の土台になる中核プロンプト。AI非依存・再利用・拡張・販売可能 -->

> **プロンプトは会社の遺伝子。AIは実行環境にすぎない。**
> Core Prompts は、どのAI(実行環境)でも同じ会社として振る舞わせるための中核プロンプト群です。
> AI社員定義・Content Factory・各製品のプロンプトは、すべてこの土台の上に立っています。

## 設計4原則

| 原則 | 実装 |
|------|------|
| **再利用可能** | 1プロンプト=1つの純粋な機能。組み合わせて使う(モノリシックな巨大プロンプトを作らない) |
| **拡張可能** | 「拡張ポイント」を各プロンプトに明示。追加は差し込み、本体は書き換えない |
| **販売可能** | TNF固有値はすべて {変数} 化。会社設定(00)を差し替えれば他社のDNAになる |
| **AI非依存** | プレーンテキストのみ。特定AIの機能・名前・書式に依存しない(→ 下記ガイドライン) |

## AI非依存の書き方ガイドライン(全プロンプト共通)

1. AIの製品名を本文に書かない(「あなたは◯◯です」は役割で書く)
2. ベンダー固有機能(特殊タグ・ツール呼び出し書式・モデル固有パラメータ)を使わない
3. 前提知識をプロンプト内で完結させる(「いつものように」禁止。文脈は毎回渡す)
4. 出力形式は Markdown 標準(見出し・表・リスト)のみで指定する
5. 能力の仮定は最小に(「長文が読める」程度。特定の文脈長・機能を前提にしない)

## 構成(8本+会社設定)

| # | プロンプト | 機能 |
|---|-----------|------|
| [00_company_config.md](00_company_config.md) | **会社設定** | 全プロンプトに注入する会社の変数(ここだけ差し替えれば他社で使える) |
| [01_master_system.md](01_master_system.md) | マスターシステム | 会社の一員として振る舞わせる土台(全セッションの最初に) |

| [03_task_briefing.md](03_task_briefing.md) | 仕事の依頼 | 完了定義つきで仕事を渡す標準形 |
| [04_generation_rules.md](04_generation_rules.md) | 生成ルール | 生成系タスク共通の品質・誠実性ルール |

| [08_handover.md](08_handover.md) | 引き継ぎ | セッション間・AI間の文脈移送(AI非依存の要) |

## 使い方(基本の組み立て)

```
[00 会社設定] + [01 マスターシステム] ← 毎セッションの土台
      + [02 役割装着](必要な役職を1つ)
      + [03 仕事の依頼](タスクごと)
      + 必要に応じて [04 生成ルール] / [05 検品] / [06 意思決定] / [07 振り返り]
セッションを跨ぐとき → [08 引き継ぎ]
```

- AI社員の `Prompt.md`(01_AI_EMPLOYEES)は「00+01+02を役職向けに焼き込んだ完成形」。
  日常はそちらを使い、**新しい役職・新しいAI・販売版**を作るときにこの Core Prompts から組む

## 販売時の手順(製品化)

1. `00_company_config.md` を購入者の会社情報で書き換えてもらう(それだけで全体が動く)
2. 同梱物:本フォルダ+使い方ガイド(08_DOCUMENTATION 規格)
3. 免責・思想ブロック(06_PRODUCTS/06_SHARED_LIBRARIES)を同梱する

## メンテナンス

- 変更は「拡張ポイントへの追記」を優先。本体の書き換えは影響範囲(全社員・全製品)を確認してから
- AI置換時の扱い → `10_TNF_PLAYBOOK/13_ai_migration.md`(補正は追加指示で吸収し、本体を守る)
