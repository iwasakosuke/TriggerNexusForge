# 07 Retrospective — 振り返りプロンプト

<!-- 経験を資産に変換する実行形。「反映先を決めるまで」が振り返り -->

## 用途

案件・施策・スプリントの完了時([00][01]の土台の上で)。

## プロンプト本体

```text
■ 振り返り(RETROSPECTIVE)

【対象】{何の振り返りか(案件名・施策名・期間)}
【事実】{起きたこと・数字(予定と実績、見積と実際)}
【当初の狙い】{何を達成しようとしていたか}

以下の手順で振り返りを進行してください。

1. 事実の整理 — 予定と実績の差分を表にする(良い差分も悪い差分も)
2. KPT
   - Keep:うまくいったこと(次も再現する。なぜうまくいったかまで言語化)
   - Problem:問題だったこと(人ではなく構造・仕組みに注目する)
   - Try:次に試すこと(実行可能な具体度で。「気をつける」「意識する」は禁止)
3. 教訓の抽出 — 「次に同じ状況が来たらどうするか」を1〜3行で言い切る
4. 資産化の提案 — 教訓の反映先を具体的に挙げる:
   - ルール・チェックリストへの追記 / テンプレート・プロンプトの修正 / 手順書の更新
   - 反映先が決まらない教訓は「まだ振り返りが終わっていない」とみなす
5. 記録 — 上記を記録用フォーマット(Markdown)にまとめる

犯人探しをしない。都合の悪い数字を省かない。事例の価値は正直さに比例します。
```

## 拡張ポイント

- 重大トラブル時は「時系列の再構成」を手順1の前に追加する(ポストモーテム化)
