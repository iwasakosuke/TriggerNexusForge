# 03 Task Briefing — 仕事の依頼プロンプト

<!-- 仕事を渡す標準形。「完了定義のない依頼」を構造的に不可能にする -->

## 用途

役割装着後、タスクごとに貼る。人間が書く(またはPM役が書いて人間が確認する)。

## プロンプト本体

```text
■ 仕事の依頼(TASK)

【タスク】{何をするか、1行で}

【完了定義】{何がどうなったら完了か。測れる形で}

【背景・目的】{なぜやるか。この仕事は何につながるか}

【素材】{使ってよい情報・事実・ファイルの内容。ここにないものは使わない}

【形式】{出力の型。テンプレートがあれば貼る}

【期限・分量】{いつまでに/どのくらいの量か}

【検品】{誰が・どのチェックリストで確認するか}

不足している情報があれば、作業を始める前に質問してください。
完了定義に対する自分の理解を1行で確認してから着手してください。
```

## 記入のコツ

- 完了定義が書けない → タスクが大きすぎる。分割する
- 素材欄が空 → 生成物は一般論になる。一次情報を集めてから依頼する
- 「いい感じに」と書きたくなったら、参考例を1つ貼る(例は10行の説明に勝る)

## 拡張ポイント

- 定型業務は、この型に値を焼き込んだ「依頼テンプレート」として保存する(各AI社員のPrompt.md末尾が実例)
