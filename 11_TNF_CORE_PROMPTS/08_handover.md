# 08 Handover — 引き継ぎプロンプト

<!-- セッション間・AI間の文脈移送。AI非依存を実運用で成立させる要のプロンプト -->

## 用途

- 長い作業のセッションを分けるとき(文脈の劣化を防ぐ)
- **使用AIを乗り換えるとき**(→ Playbook 13章。旧AIで書き出し、新AIに読み込ませる)
- 人間への業務引き継ぎ書としてもそのまま機能する

## プロンプト本体(書き出し側)

```text
■ 引き継ぎ書の作成(HANDOVER-OUT)

このセッションの作業を、文脈を知らない別の担当者(人間またはAI)が
続行できるように、引き継ぎ書を作成してください。

# 引き継ぎ書の形式
【案件・タスク】(何の仕事か、1行)
【現在地】(どこまで終わっていて、次に何をするか)
【完了定義】(何がどうなったら完了か)
【確定事項】(すでに決まったこと。決定の理由も1行ずつ)
【未決事項】(まだ決まっていないこと・保留の理由)
【素材・参照】(使っている情報・ファイル・その場所)
【注意】(この仕事固有の制約・落とし穴・依頼者の好み)
【残作業リスト】(順番つき。次の一手を先頭に)

# 作成のルール
- このセッションを読んでいない人が、これだけで作業を再開できる粒度で書く
- 「上で述べたように」「例の件」など、セッション内でしか通じない参照を使わない
- 事実と推測を区別して書く
```

## プロンプト本体(読み込み側)

```text
■ 引き継ぎの受領(HANDOVER-IN)

以下の引き継ぎ書から作業を続行します。

{引き継ぎ書の全文}

まず、次の3点を確認してから作業に入ってください:
1. 現在地と次の一手の理解を1行で復唱する
2. 引き継ぎ書の中で不明瞭・矛盾している点があれば質問する
3. 完了定義を確認する
問題がなければ、残作業リストの先頭から着手してください。
```

## 拡張ポイント

- 定例業務(週次レビュー等)は【確定事項】に前回の結論を貼る運用で「継続性」を作る
- AI置換の並行試験(Playbook 13章 STEP 2)では、同じ引き継ぎ書を新旧AIに渡して出力を比較する
