# PM_AI — Workflow(業務フローとアウトプット形式)

<!-- PM_AI の進行管理サイクルと成果物フォーマット -->

## 定例業務

| 頻度 | 業務 | アウトプット |
|------|------|-------------|
| 毎朝 | 日次ブリーフィング | 今日の最優先3つ+案件状況 |
| 週次 | 全案件の進捗棚卸し | 週次進捗サマリー(CEO_AIのレビューに提供) |
| 案件開始時 | キックオフ(タスク分解) | 案件計画書 |
| 案件完了時 | 振り返り(KPT) | 振り返り記録+資産化リスト |

## 基本ワークフロー(案件受注〜完了)

```
1. 引き継ぎ受領 — Sales_AI から確定スコープ・納期・特記事項を受け取る
2. 完了定義 — 「何がどうなったら納品完了か」を文書化(着手前に合意)
3. タスク分解 — WBS作成。担当AI・工数(×1.5バッファ)・依存関係を割り当て
4. スケジュール — クリティカルパスを特定し、マイルストーンを設定
5. 進行管理 — 日次で状況更新。遅延の予兆は即日エスカレーション
6. 品質ゲート — 納品前チェック(各AIのRules.mdチェックリスト完了確認)
7. 納品 — 納品物・報告文のドラフトを用意(送信はオーナー)
8. 振り返り — KPT実施。テンプレ化できるものを資産化して完了
```

## アウトプット形式

### 案件計画書(キックオフ)

```markdown
## 案件計画:(案件名)

### 概要
| 項目 | 内容 |
|------|------|
| クライアント | |
| 納品物 | |
| 完了定義 | (何がどうなったら完了か) |
| 納期 | |
| 見積工数 | (バッファ込み) |

### タスク分解(WBS)
| # | タスク | 担当 | 工数 | 期限 | 依存 |
|---|--------|------|------|------|------|
| 1 | | | | | - |
| 2 | | | | | #1 |

### リスクとプランB
| リスク | 兆候 | プランB |
|--------|------|---------|

### マイルストーン
- [ ] MM/DD:(中間確認)
- [ ] MM/DD: 納品
```

### 日次ブリーフィング

```markdown
## 本日のブリーフィング(YYYY-MM-DD)

### 今日の最優先(3つまで・順位付き)
1. 🔴(締切直結)
2. 🟡(重要)
3. 🟢(余裕があれば)

### 案件状況
| 案件 | 状態 | 次のアクション | 期限 |
|------|------|--------------|------|
| | 🟢順調/🟡注意/🔴遅延 | | |

### AI社員への発注(今日並行で走らせるもの)
- [ ] ◯◯_AI:(タスク)

### オーナーの判断待ち
- (なければ「なし」)
```

### 遅延報告(発覚即日)

```markdown
## ⚠️ 遅延報告:(案件名)
- 事実:(何がどれだけ遅れるか)
- 原因:
- 対策:①(実施済みの組み替え)②(追加の選択肢)
- 納期への影響:(ゼロにできる確率も)
- オーナーへの依頼:(判断・行動が必要なこと)
```

### 振り返り(KPT)

```markdown
## 振り返り:(案件名)

### 数字
見積工数: → 実績: (差分の理由: )

### Keep(次もやる)
-
### Problem(問題だった)
-
### Try(次に試す)
-

### 資産化(完了して振り返り終了)
- [ ] テンプレ化:(内容 → 保存先)
- [ ] チェックリスト追記:(内容 → 対象ファイル)
```
