# 08 Responsive Engine — レスポンシブエンジン

<!-- 「どの画面でも成立する」ための判断ロジック。モバイルファーストが唯一の正解 -->

## 入出力契約

| 方向 | 内容 |
|------|------|
| 入力 | 媒体(Web / メール / バナー=固定)+コンテンツ構造 |
| 出力 | レスポンシブ仕様(ブレークポイント・可変ルール・媒体制約) |

## 原則

1. **モバイルファースト** — 読者の8割はスマホ。PCは「広がった場合」として設計する
2. **ブレークポイントは最小限** — 768px の1つを基本(必要時のみ1080px追加)
3. **内容が同じなら構造も同じ** — モバイルで要素を隠さない(隠したくなる要素は最初から不要)

## 可変ルール(Web)

| 対象 | ルール |
|------|--------|
| 文字 | `clamp()` で可変(例:H1 `clamp(1.75rem, 5vw, 2.75rem)`)。本文16pxは死守 |
| レイアウト | Grid の `auto-fit + minmax` で列数を自動可変(メディアクエリを書かずに済む形を優先) |
| 画像 | `max-width: 100%` + `width/height` 属性(CLS防止)+ 表示幅2倍までのファイルサイズ |
| 余白 | セクション 96px → モバイル 64px / ガター 24px → 16px |
| FVの画像 | モバイルでは画像を上、テキストを下に(order 入れ替え) |
| 表 | モバイルでは `overflow-x: auto` の横スクロール容器に入れる(潰さない) |

## タップ・操作(モバイル)

- タップ領域 44×44px 以上 / 隣接タップ要素の間隔 8px 以上
- 電話番号は `tel:` リンク / 固定CTAバー(追従)は1つまで・高さ64px以下

## 媒体別の制約マップ

| 媒体 | 制約 |
|------|------|
| LP・Webサイト | 上記の可変ルールすべて適用 |
| バナー・サムネ | **固定サイズ**(→ 04 Grid のキャンバス)。可変しない代わりにサイズごとに作り分ける |
| メール(メルマガ) | メディアクエリ非対応環境あり → 1カラム・幅600px・インラインスタイル前提 |
| WordPress | テーマの挙動に依存 → 標準ブロックのみ使用(→ LP Builder Module 10)で崩れを回避 |

## 検証手順(公開前)

```
1. 375px(スマホ小)/ 768px(タブレット)/ 1280px(PC)の3点で確認
2. 文字の折り返し(キャッチコピーの不自然な改行位置)をチェック
3. 横スクロールが発生していないか(body基準)
4. タップ要素の押しやすさを実機で確認
```

## 出力形式

```yaml
responsive:
  breakpoints: [768]
  fluid_type: "clamp(min, vw, max) を使用する要素リスト"
  media_constraints: "(媒体別制約の適用内容)"
```
