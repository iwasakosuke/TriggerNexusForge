## STEP6:実案件シミュレーション(3ケース)

各ケースを「問い合わせ→Sales_AI→サービス選定→見積→PM_AI→制作/導入→QA→納品→継続契約」で通しでシミュレーションした。

### CASE A:美容室「ホームページを新しくしたい」

| 工程 | 内容 |
|------|------|
| 問い合わせ | 「ホームページを新しくしたい」という短い問い合わせ |
| Sales_AI | 24時間ルールで一次返信(`sales_messages.md`「1. 一次返信」)。ヒアリング日程調整へ |
| サービス選定 | ヒアリングで「単一ページで十分」と判明 → **02 LP制作**(01 AI Web制作ではなく、ページ数の実態に合わせて選定) |
| 見積 | 竹プラン280,000円(初回受注なら150,000円)。`sample_proposal_seitai.md`(整体院サンプル)を美容室向けに書き換え(業種テンプレートを`beauty_salon.md`に差し替え) |
| PM_AI | 受注確定後、案件シート作成(`project_sheet.md`)、WBS(ヒアリング→構成承認→制作→検品→納品) |
| 制作/導入 | `06_PRODUCTS/01_LP_BUILDER`で美容室プリセットを使用しLP生成 |
| QA | `06_REVIEW`工程+`09_KNOWLEDGE_HUB/06_WEB/Checklist.md`で検品 |
| 納品 | `07_DELIVERY`の納品書テンプレートでオーナーが納品実行 |
| 継続契約 | 05(コンテンツ制作代行)へのアップセルを提案(納品後フォロー、`sales_messages.md`「フォロー」を使用) |

### CASE B:中小企業「AIで事務作業を減らしたい」

| 工程 | 内容 |
|------|------|
| 問い合わせ | 「AIで事務作業を減らしたい」という漠然とした相談 |
| Sales_AI | 一次返信+ヒアリングで「何の事務作業か」を具体化(SPIN的ヒアリング、`Sales_AI/Knowledge.md`準拠) |
| サービス選定 | 「案件登録と請求書作成に毎週数時間かかっている」と判明 → **03 AI業務自動化・導入支援** |
| 見積 | 竹プラン300,000円(診断+スクリプト実装+マニュアル) |
| PM_AI | 業務フロー可視化(`master_flow.md`型の状態設計を応用)→WBS作成 |
| 制作/導入 | `05_AUTOMATION/scripts/init_project.sh`のような「引数1つで定型処理を済ませる」設計思想を、顧客の案件登録・請求フローに応用したスクリプト/テンプレートを作成 |
| QA | 動作テスト(冪等性・エラー時の安全な停止を確認。init_project.shで確立したパターンを踏襲) |
| 納品 | 運用マニュアル+スクリプト一式を納品。導入時の操作を一緒に確認 |
| 継続契約 | 月次保守契約、または追加業務の自動化(クロスセル) |

### CASE C:個人事業主「SNSとnoteを継続して発信したい」

| 工程 | 内容 |
|------|------|
| 問い合わせ | 「SNSとnoteを継続して発信したい」という相談 |
| Sales_AI | 一次返信+ヒアリングで媒体の優先順位・更新頻度を確認 |
| サービス選定 | **05 AI Content/note/SNS運用支援**(継続契約前提のため即座に確定しやすい) |
| 見積 | 竹プラン70,000円/月(note月2本+X単発6本+スレッド1本) |
| PM_AI | 月次サイクルのWBS(Content Factoryの型:入力シート→構成承認→本文→検品を毎月回す) |
| 制作/導入 | `02_CONTENT_FACTORY`の01_INPUT〜07_CHECKLISTの工程をそのまま運用 |
| QA | 別セッション検品(このセッションで確立したパターン:NGワード・誇張表現・未検証数字のチェック) |
| 納品 | 月次で成果物を納品(状態:approved→公開はクライアント自身、またはオプションで代行) |
| 継続契約 | サービスの性質上、最初から継続契約。クロスセルとして04(バナー)を提案し「文章+画像のフルセット」化 |

### シミュレーションからの気づき

- 3ケースとも、**サービス選定はヒアリング後に確定する**(問い合わせ文面だけでは仮説にとどまる)。SERVICE_CATALOG.mdの「Sales_AI連携ルール」はあくまで一次返信時点の仮説作りに使うものであり、確定はヒアリング後という運用ルールを徹底する必要がある
- CASE B(自動化支援)は、他の2ケースと異なり「何を自動化するか」の特定にヒアリングの比重が大きい。想定問答(`meeting_kit.md`)に自動化支援向けの質問例がまだないため、追加を検討する
- CASE A・Cは既存の`_sales_kit`一式(提案書・商談キット・営業文)がそのまま使えたが、CASE Bは`meeting_kit.md`のヒアリングシートを自動化支援向けに一部調整する余地がある

### 見つかった問題と対応

| # | 指摘 | 対応 |
|---|------|------|
| 1 | 04(Banner Creative)が「テンプレート化済み」と「未整備」を同時に主張する自己矛盾。この状態で竹・松を受注すると時給が7,500円まで崩壊する | 竹・松の販売を停止し、梅(個別設計・時給7,500円を明記)のみ提供に縮小。テンプレート整備後に再展開する方針を明記 |
| 2 | 01の工数見積(竹12h)が、LP1ページ竹(6h)に対しページ数8倍・単価1.8倍なのに工数2倍という非現実的な数字だった | 「1ページあたり+1.5h」で再計算し18hに修正。納期目安も5→15営業日に見直し |
| 3 | MONTHLY_300K_MODEL.mdのモデルB「340,000円」が、単発LP獲得月限定の数字であるにもかかわらず「月30万円」の看板として扱われていた | 「継続的に固い金額(140,000円)」と「単発が乗った月(340,000円)」を分けて明記。継続契約を3〜4社に増やすことを当面の現実的な目標として追記 |
| 4 | Sales_AI連携ルールの表が、社内オペレーション用なのか顧客提示用なのか区別されていなかった | 表の冒頭に「社内オペレーション用・顧客提示への転用禁止」を明記し、01・04は推奨時に実績ゼロ/未提供である旨を伝える指示を追加 |
| 5 | 01の「使用するTNF資産」が`INDUSTRY_TEMPLATES`(単一ページLP向け)を挙げていたが、複数ページ構成にはそのまま使えない | 注記を追加し、訴求軸・ターゲット心理の部分のみ参考にする旨を明記 |
| 6 | 01の提供価値に「短納期・明朗価格を実現」という、実績なしでの断定表現があった | 「実測時間は初回受注後に追記する」という正直な表現に差替え |
