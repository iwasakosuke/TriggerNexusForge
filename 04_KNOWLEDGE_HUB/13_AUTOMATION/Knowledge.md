# AUTOMATION Knowledge

## 自動化のROI判断(作る前に計算する)

```
自動化の価値 = (1回あたりの削減時間 × 発生頻度 × 継続期間) − (構築コスト + 保守コスト)
```

- 目安:**月2時間以上削減できるなら着手を検討**。月10分の作業に3日かけない
- 頻度が読めないものは、手動で3回やってから判断する(2回ルールの実装)

## 自動化の階段(いきなり全自動にしない)

```
1. 手順書化   : 手順を書き出す(これだけで属人化が消える)
2. テンプレ化 : 毎回同じ部分を型にする
3. 半自動化   : AIやスクリプトで下書き・下処理(人間が最終実行)
4. 全自動化   : 人間の関与なし(監視とエラー通知が必須になる)
```

- 多くの業務は**2〜3で十分**。4に進むのは「失敗してもリカバリ可能」なものだけ

## 手段の選び方

| 手段 | 向いているもの |
|------|--------------|
| プロンプトテンプレート | 文章生成・変換(Content Factoryはこれ) |
| シェル/Pythonスクリプト | ファイル処理・定型変換・一括操作 |
| GitHub Actions | リポジトリ起点の定期実行・チェック |
| ノーコード(n8n/Zapier等) | 外部サービス連携(通知・転記) |

## 設計原則

- **冪等性**: 2回動いても壊れない(重複送信・二重処理の防止)
- **可視性**: 何をしたかログを残す。静かに失敗させない
- **手動の逃げ道**: 自動化が壊れても手動で回せる手順書を残す
