# TNF Core Engine — 動くMVP(v0.1)

<!-- TNF初の「実際にブラウザで動く」プロダクト。業種・ターゲット・目的からLP一式を生成するWebアプリ -->

> **入力3つ、ボタン1つ。ブラウザだけで動く。**
> 業種・ターゲット・目的を入力して Generate を押すと、
> USP・キャッチコピー・LP構成・HTML・CSS を生成するWebアプリです。

![Version](https://img.shields.io/badge/version-0.1_MVP-F25C05) ![Runtime](https://img.shields.io/badge/runtime-browser_only-success) ![Deps](https://img.shields.io/badge/dependencies-zero-1B2A41)

## 起動方法(3秒)

```
app/index.html をブラウザで開く。以上。
```

サーバー・ビルド・インストール・APIキーは一切不要です(ダブルクリックで動きます)。

## 画面と機能

| 画面 | 内容 |
|------|------|
| 入力 | 業種(必須)/ ターゲット(空欄なら推奨を提案)/ 目的(体験申込・問い合わせ・予約・購入・資料請求) |
| Generate後 | タブ切り替えで **USP / キャッチコピー(3案)/ LP構成(8セクション)/ HTML / CSS / プレビュー** |
| 出力操作 | HTML・CSSのコピー&ダウンロード、iframeでのLPプレビュー表示 |

**対応業種プリセット**: 整体院・美容室/サロン・パーソナルジム・士業・オンライン講座・飲食店(6業種)。
プリセット外の業種は汎用テンプレート(【要記入】枠つき)で生成します。

## 動作検証済み(2026-07-06)

Playwright+Chromiumによる自動テストで以下を確認済み:

- プリセット業種で USP/キャッチ3案/構成8行/HTML/CSS/プレビュー描画がすべて出力される
- 未対応業種(例:ドローン点検)で汎用フォールバックが動作する
- 業種未入力でバリデーションエラーが表示される
- コンソールエラー・ページエラー:0件

## 技術スタック(現在と将来)

### 現在(v0.1 MVP)— 「確実に動く」を最優先

| 層 | 採用 | 理由 |
|----|------|------|
| フロント | **Vanilla HTML/CSS/JS**(ビルド不要・依存ゼロ) | ダブルクリックで動く=デモ・配布・検証が最速。壊れる部品がない |
| 生成 | ルールベース(data.js のナレッジ) | APIキー不要でオフライン動作。社内資産(業種テンプレ・Design Engine)をコード化 |
| 状態 | メモリ内オブジェクト | MVPに永続化は不要 |

### 将来の拡張パス(段階的に載せ替え)

| 段階 | 変更 | 備考 |
|------|------|------|
| v0.2 | 生成エンジンを **Claude API** に差し替え | `TNFEngine.generate(input)` のインターフェースは不変(アダプタ設計済み)。LP Builder の Modules/ のプロンプトをそのまま搭載 |
| v0.3 | **Next.js(App Router)+ TypeScript** へ移行 | APIキー秘匿のためのサーバー(Route Handlers)が必要になるタイミングで移行。Vercelデプロイ |
| v0.4 | 永続化:**Supabase**(Postgres+認証) | project.yaml スキーマ(LP Builder Modules/README.md)をそのままテーブル化 |
| v1.0 | 課金(**Stripe**)+公開 | Roadmap 2028年のプロダクト販売に接続 |

**選定理由**: Next.js/Vercel/Supabase/Stripe は「一人開発で運用が最も軽い」構成。
エコシステムが大きくAIコーディング支援(Claude Code)との相性も最良のため、拡張速度が出る。

## アーキテクチャの要点(拡張しやすさの担保)

- **エンジンとUIの分離**: `engine.js` は純粋関数(入力→出力)。UIを知らない。API化・テスト・差し替えが容易
- **ナレッジとロジックの分離**: 業種データは `data.js` に隔離。業種追加=データ追加のみ(エンジン改変不要)
- **入出力契約は LP Builder と共通**: input(業種・ターゲット・目的)→ result(usp/catches/structure/html/css)は
  `01_LP_BUILDER/Modules/` の設計に準拠。プロンプト版とアプリ版が同じ概念モデルで進化する

## 位置づけ(LP Builder との関係)

| | 01_LP_BUILDER | 00_CORE_ENGINE(本製品) |
|--|--------------|------------------------|
| 形態 | プロンプトシステム(AIチャットで実行) | **Webアプリ(ブラウザで実行)** |
| 生成品質 | 高(LLMによる文脈生成) | 中(ルールベース。ただし即時・無料・安定) |
| 役割 | 実案件の制作エンジン | デモ・見込み客体験・将来のSaaSの骨格 |

将来 v0.2 で Claude API を載せると、LP Builder のプロンプト資産がこのアプリの生成品質になる(合流点)。

## 制約(MVPの割り切り)

- 生成文章はテンプレートベース。実績・数字は【要記入】枠(事実はユーザーが入れる思想は全製品共通)
- ペルソナ生成・FAQ個別生成などの深い生成は v0.2(API版)から
- 保存機能なし(ダウンロードで持ち出す)
