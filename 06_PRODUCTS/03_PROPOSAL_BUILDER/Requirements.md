# Proposal Builder — Requirements(要件定義)

## 機能要件

| # | 要件 | 優先度 |
|---|------|:---:|
| F1 | ヒアリングメモ(自由記述)から課題を構造化できる | 必須 |
| F2 | 課題起点の提案書ドラフト(5部構成)を生成できる | 必須 |
| F3 | 松竹梅3プランの見積(スコープ・修正回数明文化)を生成できる | 必須 |
| F4 | ヒアリング前の質問リスト・想定問答を生成できる | 必須 |
| F5 | 断り・値引き対応・フォローの文例が付属する | 推奨 |

## 非機能要件(製品三原則)

### 再利用性
- 商材・単価・支払条件は変数化(制作業のデフォルト値をサンプルとして同梱)
- 提案書の構成(課題→解決→進め方→価格→次のステップ)は業種非依存の型として維持

### 販売可能性
- ヒアリングメモ→提案書ドラフトまで30分以内を体験価値の基準にする
- 「送信前に必ず人間が確認する」を製品の思想として明記(誤送信・過剰約束は購入者の損害になる)

### 拡張性
- 文例集は1状況1ファイルで追加できる構造
- 見積の型(3プラン)は業種別プリセットを後付けできる設計

## 制約・非対応

- 契約書の生成はスコープ外(法的文書は専門家領域と明記)
- 価格の「正解」は提示しない(考え方と相場観の提供まで)
