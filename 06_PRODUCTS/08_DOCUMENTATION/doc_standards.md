# Doc Standards — ドキュメント規格

## 販売物に必ず同梱する4点

| ドキュメント | 内容 | 基準 |
|-------------|------|------|
| はじめに(START_HERE) | 全体像・必要環境・最初の一歩 | 5分で読める |
| 導入ガイド | セットアップ手順(スクショ付き) | 手順どおりで必ず動く |
| 運用ガイド | 日常の使い方・よくある躓き | 躓き→解決の形式 |
| FAQ+サポート方針 | 質問窓口・対応範囲・免責 | 期待値の明文化 |

## 書き方の規格

- **読者はその分野の初心者と想定する**(専門用語は初出で補足。前提知識は最初に明示)
- 手順は1ステップ=1アクション。「〜して、〜して、〜する」と繋げない
- 手順には「うまくいったときの状態」を書く(自分が正しい場所にいると分かる)
- 躓きポイントには「⚠️」を付けて先回りで注意する
- 更新日をドキュメント冒頭に明記する

## 導入ガイドの型

```markdown
# (製品名)導入ガイド(更新日:YYYY-MM-DD)
## 必要なもの(環境・所要時間)
## STEP 1: (アクション)
(手順)→ ✅ こうなればOK
⚠️ よくある躓き:(症状→対処)
## STEP 2: ...
## 完了チェック(すべて✓で導入完了)
```
