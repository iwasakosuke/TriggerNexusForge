# 10_FEEDBACK — フィードバック

<!-- 利用者の声の収集と、製品改善への変換装置。「買った人の声が最優先の開発指示」 -->

利用者(自社・クライアント・購入者)からのフィードバックを管理します。

| ファイル | 内容 |
|---------|------|
| [feedback_log.md](feedback_log.md) | フィードバックログ(全製品共通) |

## 収集ルート

| ルート | タイミング |
|--------|-----------|
| 自社利用(ドッグフーディング) | 使うたびの違和感をその場で記録(最初で最大の情報源) |
| クライアント利用 | 案件振り返り(KPT)時に製品への示唆を抽出 |
| 購入者 | 購入後アンケート・問い合わせ・SNSの言及 |

## 処理フロー

```
記録(ログに1行)→ 分類(バグ/分かりにくい/機能要望/褒め)
→ 判断(対応する/しない+理由)→ 反映(製品のRoadmapへ)→ 回答(必要な場合)
```

## ルール

- ネガティブな声ほど資産(改善の地図)。感情と切り分けて事実を拾う
- 「対応しない」判断も理由つきで記録する(同じ検討を繰り返さない)
- 褒められた点は販売素材へ(許可を得て `09_MARKETING` の実績に)
