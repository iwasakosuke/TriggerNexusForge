# TNF LP Builder — Workflow(使用手順 v0.1)

<!-- 入力から公開までの手順書。初回90分を想定 -->

## 全体フロー

```
[準備 5分]     Prompt.md のマスタープロンプトをAIに貼る
     ↓
[入力 5分]     業種を書く(ターゲット・オファー・実績もあれば書く)
     ↓
[生成I 10分]   STAGE 0〜3:入力確定→USP→キャッチ→構成
     ↓
[承認 5分]     ★構成表を確認して「承認」(修正があればここで指示)
     ↓
[生成II 10分]  STAGE 4〜7:全文章→CTA→HTML/CSS→WP用テキスト
     ↓
[記入 30分]    ★【要記入】を自分の事実で埋める(実績・営業時間・URL等)
     ↓
[実装 15分]    HTMLを style.css と同フォルダに配置/CSSの3変数を差し替え
               (WordPressの場合:STAGE 7 の出力を固定ページに貼る)
     ↓
[検品 10分]    ★公開前チェック(下記)→ 公開
```

★=人間にしかできない工程(それ以外はAIが行う)

## 公開前チェックリスト

- [ ] {{ }} と【要記入】の残りがゼロか(ブラウザ検索で確認)
- [ ] 実績・お客様の声はすべて事実か(掲載許可も確認)
- [ ] 【規制注意】の箇所を確認・対応したか
- [ ] CTAボタンのリンク先(フォーム・電話)が実際に動くか
- [ ] スマホで表示確認したか(FV・料金表・FAQ)
- [ ] 特商法表記/会社概要へのリンクがあるか(販売LPは必須)

## つまずいたら

| 症状 | 対処 |
|------|------|
| 出力が途中で切れる | 「続きを出力して」と返す。または STAGE 4〜7 を分割実行(Prompt.md 末尾) |
| コピーがしっくりこない | STAGE 2 に戻り「◯◯のトーンで再生成」と指示(具体的な不満を言葉に) |
| 構成を変えたい | STAGE 3 の承認前に修正指示(承認後の変更は文章の作り直しになる) |
| 色が合わない | style.css の3変数だけを変える(他は触らない) |

## TNF社内で使う場合(ドッグフーディング)

- 案件フローとの接続:`05_AUTOMATION/05_WEB_PIPELINE/web_flow.md` の STEP 2〜4 をこのツールで実行
- 検品は社内基準(`02_CONTENT_FACTORY/07_CHECKLIST/` + `09_KNOWLEDGE_HUB/06_WEB`)を追加で通す
- 使用のたびに所要時間と改善点を `../10_FEEDBACK/feedback_log.md` に記録する(v0.5 の販売素材になる)
