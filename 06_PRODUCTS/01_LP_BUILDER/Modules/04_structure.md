# Module 04 — LP構成生成 ★承認ゲート

<!-- ペルソナの検討度から構成の型を選び、8セクションを設計する。ここで人間が承認してから先へ進む -->

## 入出力契約

| 方向 | 内容 |
|------|------|
| 入力 | `project.input` + `persona` + `usp` |
| 出力 | `project.structure`(承認済み構成表)★人間の承認が必須 |

## プロンプト

```text
あなたはLP構成設計の専門家です。ペルソナが自然に説得される順番でセクションを設計してください。

# 入力
(project.input / persona / usp を貼る)

# 手順
1. persona.consideration(検討度)から構成の型を選ぶ:
   低 → PASONA(問題提起から) / 中〜高 → QUEST(絞り込み・比較対応から)
2. 8セクション前後の構成を表で設計する:
   | # | セクション | 目的 | ペルソナの心理状態 | 掲載要素 |
3. 業種特性・ペルソナ特性による標準形からの変更があれば、理由を添えて提案する
   (例:挫折経験者向け→「挫折の原因の再定義」セクションを追加)
4. 各セクションに、usp.support_points と persona.brake のどれを処理するかを割り当てる
   (どの不安がどこで解消されるかの漏れチェック)

# ルール
- goal(成約行動)への一本道にする。関係ないセクションは提案しない
- persona.brake がどこかのセクションで必ず処理されていること(未処理なら構成に追加)
- `input.facts`(実績・お客様の声)が空欄の場合、「実績・声」セクションは標準位置(5番目前後)ではなく
  **3番目前後(課題共感の直後)に前倒しする**。実績への警戒を後半まで放置すると離脱するため
  (詳細は`05b_no_track_record.md`)

# 出力形式
構成表+「変更点と理由」+「ブレーキ処理マップ(不安→処理セクション)」
最後に必ず:「この構成で進めてよいですか?(修正があればどうぞ)」で停止する
```

## サンプル入力

Module 01〜03 のサンプル出力(パーソナルジム/佐藤美咲/女性×個室USP)を貼る。

## サンプル出力

型:QUEST(検討度:中。比較段階のため絞り込みから入る)

| # | セクション | 目的 | ペルソナの心理 | 掲載要素 |
|---|-----------|------|---------------|---------|
| 1 | FV | 「私のためのジムだ」と3秒で認識させる | どうせここも同じでしょ | キャッチ+安心要素3点+CTA |
| 2 | 挫折の再定義 | 「続かない=意志の問題」を否定する | 私は意志が弱いから… | 挫折の原因分析(仕組みの不在) |
| 3 | 課題共感 | 悩みの言語化 | そうそう、それ | pains 3つをそのまま |
| 4 | 解決策 | 続く仕組みの提示 | ここは何が違うの? | USP+サポート3点 |
| 5 | ベネフィット | 通った先の生活の変化 | 良さそうだけど私にできる? | Before→After 3つ |
| 6 | 実績・声 | 同じ悩みの人の証拠 | 本当かな | 【要記入】枠×2 |
| 7 | 料金・体験の流れ | 透明性と最初の一歩の軽さ | いくら?何をされる? | 初回体験3,000円+当日の流れ |
| 8 | FAQ | 残った不安の先回り | あと一歩が怖い | Module 07 の出力 |
| 9 | 最終CTA | 背中を押す | 今度でいいか… | CTA+不安解消 |

**標準形からの変更**: 「挫折の再定義」を追加(persona.tried に挫折経験×3。ここを処理しないと何を言っても「どうせ続かない」で弾かれるため)。

**ブレーキ処理マップ**: 「また続かない不安」→ #2・#4 / 「見られる恥ずかしさ」→ #1・#4 / 「きつい食事制限への警戒」→ #8(FAQ)

→ **「この構成で進めてよいですか?」**(承認後、`project.structure` に `approved: true` を記録して Module 05 へ)
