# Module 03 — USP生成

<!-- 「なぜ他ではなくここか」を1行に固める。強み(事実)×ペルソナの悩みの交差点がUSP -->

## 入出力契約

| 方向 | 内容 |
|------|------|
| 入力 | `project.input` + `project.persona` |
| 出力 | `project.usp`(採用USP+サポートポイント) |

## プロンプト

```text
あなたはポジショニングとUSP設計の専門家です。
強み(事実)とペルソナの悩みの交差点から、USPを設計してください。

# 入力
(project.input と project.persona を貼る)

# 手順
1. この業種の競合LPが「共通して言っていること」を3つ挙げる(=言っても選ばれない要素)
2. input.strengths の各項目を、persona.pains / brake と突き合わせ、
   「どの強みが、どの悩み・不安を解消するか」の対応表を作る
3. USP候補を3案作る。各案:USP文(1行)/ 対応する悩み / 根拠となる強み(事実)
4. 推奨1案を選ぶ。基準:①ペルソナのブレーキ(不安)を最も強く外す ②競合の共通項と被らない
5. 採用USPを支える「サポートポイント」を3つに整理する(FVの安心要素・ベネフィットの種になる)

# ルール
- USPは事実(strengths)の裏付けがあるものだけ。裏付けがない魅力的な案には【要記入:裏付け】を付ける
- 「高品質」「安心」「丁寧」などの抽象語だけのUSPは禁止(名詞と数字で)
- `input.facts`(実績・お客様の声)が空欄の場合、3案の中に**裏付け不要な案を必ず1つ含める**
  (「実績が少ない/まだない」こと自体を動かせない事実として使う案。詳細は`05b_no_track_record.md`)

# 出力形式(YAML)
usp:
  main: (採用USP・1行)
  reason: (採用理由)
  support_points: [3つ]
  rejected: [不採用2案+理由1行]
```

## サンプル入力

Module 01+02 のサンプル出力(パーソナルジム/佐藤美咲)を貼る。

## サンプル出力

```yaml
usp:
  main: "女性トレーナーと完全個室で、『また続かなかった』を終わらせるパーソナルジム"
  reason: >
    ペルソナの最大のブレーキは「続かない自分」への諦めと「見られる恥ずかしさ」。
    競合の共通項(結果コミット・マンツーマン指導)と被らず、
    強み(全員女性・完全個室・LINE食事サポート)がすべて事実で裏付く。
  support_points:
    - "トレーナーは全員女性 × 完全個室 — 誰にも見られず相談できる環境"
    - "LINEの毎日食事サポート — ジムにいない167時間を放置しない仕組み"
    - "駅徒歩3分 — 『行くのが面倒』という挫折理由を物理的に消す"
  rejected:
    - "駅近No.1の通いやすさ(→根拠なき最上級で使用不可。徒歩3分は事実として使う)"
    - "科学的トレーニングで最短の結果(→競合の共通項と同じ土俵。差別化しない)"
```
