# Module 05 — セクションコピー生成

<!-- 承認済み構成の各セクションの文章を書く。パイプラインで最も「書く」モジュール -->

## 入出力契約

| 方向 | 内容 |
|------|------|
| 入力 | `project.input` + `persona` + `usp` + `structure`(approved: true のもののみ) |
| 出力 | `project.copy`(全セクションの確定文章) |

## プロンプト

```text
あなたはセールスコピーライターです。承認済みの構成に沿って、
全セクションの文章を書いてください。読者は「persona」のたった1人です。

# 入力
(project.input / persona / usp / structure(承認済み)を貼る)

# 執筆ルール
- ペルソナの言葉(pains の表現)をコピーに使う(読者は自分の言葉に反応する)
- ベネフィットは Before→After の変化で書く(機能の説明にしない)
- 一文60字以内・です・ます調。見出しは20字以内
- FVキャッチは10案(型違い)作ってから推奨1案を選ぶ
- 実績・声・数字は input.facts にあるものだけ。空なら【要記入】枠を作る
- 効果の断定(必ず痩せる等)は書かない。「〜を目指す」「個人差があります」を使う【規制注意】

# 出力形式(YAML・セクションごと)
copy:
  fv: { catch: , catch_candidates: [10案], sub: , points: [3つ] }
  redefine: { heading: , body: }        # 構成にある場合のみ
  problems: { heading: , items: [3つ], bridge: }
  solution: { heading: , body: }
  benefits: { heading: , items: [{title:, before_after:} ×3] }
  proof: { heading: , items: [声 or 【要記入】枠] }
  price: { heading: , plans: [...], flow: [当日の流れ], note: }
  last_cta: { heading: , push: , relief: }
```

## サンプル入力

Module 01〜04 のサンプル出力を貼る(構成は承認済みとする)。

```yaml
      「いつでも行ける」は「いつか行く」に変わるからです。
      必要なのは根性ではなく、続けさせてくれる仕組みでした。

      - "ジムに入会したのに、3ヶ月で行かなくなった"

      - title: "ジムの外の167時間が変わる"
        before_after: "家に帰ると元の食生活 → LINEの毎日サポートで無理なく食事が整う"

        before_after: "遠くて足が遠のく → 駅徒歩3分。買い物ついでに通える"
  proof:
    items:
      - "【要記入:お客様の声1(掲載許可を得た実際の声)】"
      - "【要記入:お客様の声2】"
  price:
    plans:
      - { name: "初回体験60分", price: "3,000円", note: "カウンセリング+体験トレーニング" }
    flow: ["カウンセリング(15分)", "体験トレーニング(35分)", "質問タイム(10分)※勧誘はしません"]
```
