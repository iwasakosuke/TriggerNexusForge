## 機能要件(10機能と受け入れ基準)

| # | 機能 | モジュール | 受け入れ基準(これを満たせば合格) |
|---|------|-----------|--------------------------------|
| F1 | 入力フォーム | 01 | 4項目(業種・ターゲット・目的・強み)+任意2項目。必須/任意・検証ルールが定義済み。業種のみでも完走する |
| F2 | ペルソナ生成 | 02 | 3案(悩みは本人の言葉・挫折経験・引き金/ブレーキ)+推奨1人+検討度判定が出る |
| F3 | USP生成 | 03 | 競合の共通項を除外し、強み(事実)×悩みの対応から3案+推奨+サポートポイント3つが出る |
| F4 | LP構成生成 | 04 | 検討度で型を選び、構成表+不安処理マップを出して承認ゲートで停止する |
| F5 | セクションコピー生成 | 05 | 承認済み構成の全セクション本文(キャッチ10案込み)がYAML形式で出る |
| F6 | CTA生成 | 06 | ボタン文言5案+不安解消コピー+3箇所の配置+導線判定(Web/LINE/電話)が出る |
| F7 | FAQ生成 | 07 | ペルソナのブレーキ起点の5〜7問が不安の大きい順に出る(正直な回答・100字以内) |
| F8 | HTMLテンプレート生成 | 08 | 対応表→lp.html準拠の完成HTML→残作業リストの3点が出る |
| F9 | CSSテンプレート生成 | 09 | style.css前提の3変数指定+理由+代替案1つが出る(コントラストAA確認込み) |
| F10 | WordPress向けコンテンツ生成 | 10 | wordpress.md形式(標準ブロックのみ・リンク先併記)で全セクションが出る |

## アーキテクチャ要件(v0.2で追加)

| 要件 | 基準 |
|------|------|
| モジュール独立性 | 各モジュールは入出力契約(→ Modules/README.md)だけで接続。単体で再実行できる |
| サンプル同梱 | 全モジュールにサンプル入力・サンプル出力が付属し、共通題材で貫通している |
| Webアプリ化対応 | フォーム定義(検証込み)・状態スキーマ(project.yaml)・承認UIの要件が文書化されている |

## 品質要件(全機能共通)

| 要件 | 基準 |
|------|------|
| 事実の非捏造 | 未入力の実績・数字・声は必ず【要記入】枠になる(勝手に埋めたら不合格) |
| 誇大表現ゼロ | 「絶対」「100%」「誰でも簡単に」「必ず治る/痩せる」が出力に含まれない |
| 規制への配慮 | 業種規制に触れうる表現に【規制注意】+代替案が付く |
| 自己検品 | 最終出力に【要記入】【規制注意】の残数レポートが付く |

## 非機能要件(MVP)

### 再利用性
- テンプレートは自己完結(社内資産への参照なしで動く)
- CSSカスタマイズ面は3変数に限定(--color-primary / secondary / base)

### 販売可能性
- 前提知識:「コピペとテキスト編集ができる」以上を要求しない
- 初回完走の想定時間:90分以内
- 免責・思想(ドラフトツールである/成果保証しない)を README に明記

### 拡張性
- 業種対応の強化=業種プレイブックの追加(エンジン本体の改変不要)
- 実行例の追加=Examples に1ファイル追加

## スコープ外(明文化)

- 画像生成/フォーム設置/サーバー・ドメイン作業/効果測定ツールの設定
- 法規制の最終判断(【規制注意】は注意喚起であり、法務チェックの代替ではない)
