# 06_PRODUCTS — Product Factory(商品開発部門)

<!-- 自社利用→クライアント利用→販売、と価値が3段活用されるAIプロダクトの管理部門 -->

> **一度作ったものを、三度売る。**
> Product Factory は、TNFの業務から生まれた仕組みを
> **①自社利用 → ②クライアント利用 → ③販売用プロダクト**として再利用する部門です。
> Roadmap の2028年「プロダクト化」(受託と売上の分離)の主戦場。

## プロダクト開発の三原則

1. **再利用性** — TNF固有の値(社名・色・トーン)はすべて変数化し、差し替えだけで他社でも動く形にする
2. **販売可能性** — 「自分が買うか?」を通過したものだけをプロダクトと呼ぶ。ドッグフーディング(自社利用)が最初の関門
3. **拡張性** — 機能追加はファイル追加で済む構造にする(既存ファイルの書き換えを要求する設計は失格)

## 各プロダクトのファイル構成(共通)

| ファイル | 役割 |
|---------|------|
| `README.md` | 製品概要(誰の・何を・どう解決するか/3つの利用モード) |

## 製品化の標準ステップ(全製品共通)

```
v0.1 自社利用   : 社内資産を製品の形に整える。自分の業務で使う(ドッグフーディング)
v0.5 案件投入   : クライアント案件で実戦投入。他者が使う際の躓きを潰す
v0.9 汎用化     : TNF固有値を変数化(→ 06_SHARED_LIBRARIES の規約)。第三者テスト
v1.0 販売開始   : ドキュメント完備(08)+販売ページ(09)+フィードバック窓口(10)
```

## 運用ルール

1. **社内資産が正** — 製品は社内資産(02/03/05 等)のスナップショット+汎用化。二重メンテを避けるため、改善はまず社内資産側で行い、リリース時に製品へ反映する
2. **バージョンと変更はリリースログに**(→ `07_RELEASES`)
3. **買った人の声が最優先の開発指示**(→ `10_FEEDBACK`)
4. **販売物の品質基準はS級**(→ `02_CONTENT_FACTORY/00_RULES/quality_standards.md`)
