# DAY17 — 標準契約条件とスコープ文言

Week3:Proposal Builder / 営業資料|所要目安:2〜3時間

## 今日のSprint名
Sprint 3-3「トラブルを未然に消す:標準条件の文書化」

## 今日の目的
受注後のトラブル(スコープクリープ・支払い・修正無限ループ)を防ぐ標準文言を確定する。

## 完成条件
- 標準条件書が完成:スコープの書き方・修正回数(2回)・支払条件(着手50%+納品50%)・
  検収期限・追加費用の条件・キャンセル規定・実績公開の許可確認
- 提案書テンプレートに標準条件が組み込まれている

## Claude Codeに貼る指示
```text
00_COMPANY/CLAUDE.md 確認後:
1. 01_AI_EMPLOYEES/Sales_AI/Knowledge.md(商習慣)と
   05_AUTOMATION/02_PROJECT_MANAGEMENT/project_sheet.md(スコープ欄)を参照し、
   標準条件書のドラフトを作成:07_CLIENTS/_sales_kit/standard_terms.md
2. 「よくあるトラブル→防ぐ文言」の対応表形式で(例:
   ついで修正の増殖→修正回数と対象範囲の定義文)
3. Day16のサンプル提案書に標準条件セクションを追記して
※これは社内標準の文書であり、法的な契約書は専門家確認が必要と明記すること
```

## テスト方法
「もし◯◯と言われたら」テスト3問(値引きして/ついでにバナーも/検収の返事がない)に、条件書の文言で答えられるか。

## レビュー方法
各条件を「自分がクライアントだったら不快でないか」の視点で読み直す(守りが攻撃的な文面になっていないか)。

## GitHub保存方法
standard_terms.md+提案書更新をコミット→push→CHANGELOG追記。

## 推奨コミットメッセージ
```
Day17: 標準契約条件を文書化(スコープ・修正・支払・検収)
```

## 実案件での使い方
受注時にこのまま合意文書のベースになる(法的契約書が必要な規模では専門家に確認)。
