# DAILY_ROUTINE — 朝・作業中・夜のルーティン

<!-- 毎日の型。考えなくても手が動く状態にするための習慣書 -->

## 朝のルーティン(10:00〜10:10)

```
□ START_HERE.md を開く(すべての起点)
□ CHANGELOG.md で昨日の到達点を確認
□ 今日のDAYファイルを開き、「今日の目的」と「完成条件」を音読する(30秒)
□ PM_AI の日次ブリーフィング形式で今日の最優先3つを書く:
   1.(今日のSprint=最優先)
   2.(実案件・問い合わせ対応があれば)
   3.(余力があれば:SNS発信)
□ 起動手順:01_AI_EMPLOYEES/PM_AI/Prompt.mdを貼り「今日のブリーフィングを」と依頼→05_AUTOMATION/02_PROJECT_MANAGEMENT/project_sheet.md・10_LOGS/project_log.mdを読ませて現状を渡す→08_DOCUMENTS/briefings/YYYY-MM-DD.mdに保存
□ 通知を切る(Sprint実行中はシングルタスク)
```

## 作業中のルーティン(10:10〜)

- **45分作業 → 5分休憩**のリズムを目安にする(連続2時間を超えない)
- Claude Codeへの指示はDAYファイルの指示ブロックをベースに(ゼロから書かない)
- **詰まったら15分ルール**: 15分悩んだら、詰まりの内容を書き出してClaude Codeに相談する
  (「◯◯をしようとして、◯◯を試したが、◯◯というエラー/状態になる」)
- 途中で別のアイデアが湧いたら:着手せず `08_DOCUMENTS/` にメモして戻る(脱線防止)
- 昼休憩は必ず取る(疲労状態の判断を信用しない — Mission.md)

## 夜のルーティン(終業前15分)

```
□ 今日の成果物をコミット&プッシュした(GITHUB_RULES.md の手順)
□ CHANGELOG.md・日報の日付は「実際に作業した日」であることを確認した
  (長時間セッションではセッション開始日のまま書きがち。迷ったら `git log --date=format:"%Y-%m-%d"` で答え合わせする)
□ CHANGELOG.md に1行追記した(DAY番号・やったこと・状態)
□ 日報を書いた(TEMPLATES/DAILY_REPORT_TEMPLATE.md → 08_DOCUMENTS/daily/ に保存)
□ 明日のDAYファイルを1分だけ眺めた(脳に予告を入れると朝が速い)
□ 作業を閉じる(夜に「あと少しだけ」をやらない — 休む日は完全に休むの日次版)
```

## 週次ルーティン(Day07/14/21/28 に組み込み済み)

- CEO_AI形式の週次レビュー(数字・進捗・学び・来週の最優先3つ)
- 詰まった工程をプロンプト・テンプレートに還元(検品の上流化)
- 09_ARCHIVE / improvement_log 系への記録

## 例外日の扱い

| 状況 | ルール |
|------|--------|
| 実案件・問い合わせが来た | **案件優先**。SprintはDAY番号ごと後ろにずらす(飛ばさない) |
| 体調不良・予定あり | 休む。翌日は続きのDAYから(取り返そうと2DAYやらない) |
| やる気が出ない | 完成条件を見て「最小の一歩」だけやる(15分)。始めれば大抵続く |
