> **毎朝10時にやることは1つ。このファイルを開くこと。**
> あとは下の順番に従えば、今日やるべきことに3分でたどり着きます。

## 毎朝10時の起動手順(3分)

```
1. このファイル(START_HERE.md)を開く
2. CHANGELOG.md を見て「昨日どこまで進んだか」を確認する(30秒)
3. 30_DAY_SPRINTS/ の今日のDAYファイルを開く
   → 今日が何日目か分からなくなったら CHANGELOG の最後の記録+1日目
4. DAILY_ROUTINE.md の「朝のルーティン」を実行する(5分)
5. DAYファイルの「Claude Codeに貼る指示」をコピーして作業開始
```

## 作業の順番(1日の流れ)

```
10:00 起動(上の手順)
10:10 Sprint実行 — DAYファイルの指示をClaude Codeに貼り、完成条件まで進める
      (詰まったら:DAYファイルの「テスト方法」で現在地を確認)
午後  レビュー — DAYファイルの「レビュー方法」で検品
夕方  保存 — 「GitHub保存方法」+「推奨コミットメッセージ」でコミット&プッシュ
      記録 — TEMPLATES/DAILY_REPORT_TEMPLATE.md で日報 → CHANGELOG.md に1行追記
```

## 30日間の全体地図

| 週 | テーマ | ゴール |
|----|--------|--------|
| Week1(Day01-07) | TNF LP Builder MVP | 自社LPを完成させ、ツールを実戦レベルに磨く |
| Week2(Day08-14) | Content Factory実運用 | 発信を開始し、2テーマを公開する |
| Week3(Day15-21) | Proposal Builder / 営業資料 | 提案書・料金表・営業キット一式を完成させる |
| Week4(Day22-30) | Automation / GitHub運用 / 初案件化 | 案件フローを開通させ、初案件の入口に立つ |

## 迷子になったときの復帰手順

- **昨日サボった** → 責めずに続きのDAYから再開(日付ではなくDAY番号で進む)
- **DAYが1日で終わらなかった** → 翌日同じDAYを続ける(完成条件を満たすまで次に進まない)
- **順番を変えたくなった** → 原則変えない。ただし実案件が来たら実案件優先(→ 各DAYの「実案件での使い方」)
- **何もかも分からなくなった** → `10_TNF_PLAYBOOK/README.md` → 01章から読み直す

## このOSの約束(3つだけ)

1. **1日1DAY** — 早く終わっても先に進みすぎない(余った時間はSNS発信か休憩)
2. **完成条件で判定** — 「だいたいできた」は未完了。条件を満たすまでがSprint
3. **記録して終わる** — CHANGELOG 1行+日報。記録なき日は「なかった日」になる
