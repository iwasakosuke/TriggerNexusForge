## 原則

- **main は常に「会社の現在の正」** — 壊れた状態で main にしない
- 1コミット=1つの意味。「なぜ」が書けないコミットは分割する
- 週1回は必ず push(ローカルだけの資産を作らない)

## 標準フロー

```
1. 作業前:git status で現在地を確認する(癖にする)
2. 機能単位のブランチを切る(例:feature/lp-builder-v03)
3. 動く状態ごとにこまめにコミット(メッセージ:何を・なぜ)
4. まとまったら main へマージ → push
```

## ルール

- ファイル移動は `git mv`(履歴を繋ぐ)
- ドキュメント更新は関連する変更と同じコミットに含める
- 認証情報・機密の混入は絶対禁止(→ 12章 セキュリティ)
- コンフリクトは中身を理解してから解消(機械的にどちらかを捨てない)
