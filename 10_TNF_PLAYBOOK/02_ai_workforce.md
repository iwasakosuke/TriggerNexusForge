## AI社員の構造(正典:`01_AI_EMPLOYEES/`)

1社員=1フォルダ×5ファイル(Identity / Knowledge / Workflow / Prompt / Rules)。
この構造自体がAI非依存(どのLLMにも装着できる定義書)。

## 起動の標準手順

```
1. 社員の Prompt.md のシステムプロンプトを作業AIに貼る
2. 関連する知識(09_KNOWLEDGE_HUB の該当ドメイン)を渡す
3. 依頼テンプレート(各Prompt.md内)で仕事を渡す:完了定義・素材・形式・期限
4. 出力は Workflow.md の形式で受け取り、Rules.md のチェックリストで検品する
```

※汎用の起動・依頼・検品プロンプトは `11_TNF_CORE_PROMPTS/` に集約されている。

## 運用ルール

- **1セッション1役割** — 営業と執筆を同じ会話に同居させない
- **AIは並行、人間は直列** — 発注は同時に複数、レビューは1つずつ
- **検品は生成者以外** — 別セッション・別役割・翌日の自分
- **越境させない** — 各社員の苦手分野(Identity.md)は委譲先に振り直す

## 育成(定義の改善)

- 口調・判断が合わない → その場で直させず、定義ファイルを更新してコミット(次回から効く)
- 同じ指摘が2回 → Rules.md のチェックリストに追加
- 良い出力 → 出力例ストック(02_CONTENT_FACTORYの各プロンプト末尾)に保存

## 採用(新社員の追加)

1. Roadmap の年次採用計画を確認(2027: Engineer/Marketer/Support…)
2. 既存社員の5ファイル構造をコピーして定義を書く
3. 名簿(`01_AI_EMPLOYEES/README.md`)と連携マップを更新
