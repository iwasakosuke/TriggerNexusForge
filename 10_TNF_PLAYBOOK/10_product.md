## 製品化の標準ステップ

```
v0.1 自社利用(ドッグフーディング)→ v0.5 案件投入(実測データ取得)
→ v0.9 汎用化(固有値の変数化・第三者テスト)→ v1.0 販売
```

「自分が買うか?」を通らないものを製品と呼ばない。実測データ(時間短縮・受注実績)が販売素材になる。

## 製品の必須構造

- 5ファイル(README / Roadmap / Requirements / Prompt / Workflow)+必要に応じて Modules / Templates / Examples
- 三原則:再利用性(固有値の変数化)/ 販売可能性(初心者が完走できる)/ 拡張性(追加=ファイル追加)
- 変数・バージョン規約:`06_PRODUCTS/06_SHARED_LIBRARIES/conventions.md`

## リリース手順

1. Roadmap の完了条件を満たしたか確認 → 2. 第三者視点の通しテスト
3. `07_RELEASES/release_log.md` に記録+README の状態更新 → 4. (v1.0〜)販売ページ・ドキュメント4点

## 販売後の運用

- フィードバック(10_FEEDBACK)→ 分類 → Roadmap反映 → 対応/非対応を理由つき記録
- 破壊的変更は購入者への案内文とセットでリリース
- 販売文句は誠実ライン内のみ(実測数字・個人の結果の域)
