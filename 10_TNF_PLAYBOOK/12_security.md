# 12 セキュリティ

<!-- 機密・認証情報・事故対応の手順。一人会社でも「会社」としての管理水準を保つ -->

## 情報の分類(3レベル)

| レベル | 例 | 扱い |
|--------|-----|------|
| 公開可 | 発信コンテンツ・テンプレート | 通常運用 |
| 社外秘 | 案件情報・売上・戦略 | リポジトリはprivate。発信時は許可・匿名化 |
| 機密 | 認証情報・APIキー・顧客の個人情報 | **リポジトリに置かない**(下記) |

## 認証情報の管理(絶対規則)

- コード・ドキュメント・コミット履歴に書かない(.env+.gitignore/シークレット管理を使う)
- 万一コミットしたら:**即ローテーション(無効化・再発行)**が第一手。履歴削除は第二手
- トークン・キーは最小権限で発行し、用途と発行日を記録する
- 使わなくなったキー・共有アカウントは四半期の棚卸しで削除する

## クライアント情報の扱い

- 預かった認証情報は案件終了時に削除(納品チェックに含む)
- 個人情報は必要最小限だけ受け取り、保存場所を1箇所に限定する
- スクリーンショット・デモに顧客情報が写り込んでいないか検品で確認(proofreading項目)

## AI利用時のセキュリティ

- 機密(認証情報・個人情報・未公開の顧客データ)をプロンプトに貼る前に立ち止まる
- 利用AIサービスのデータ取り扱い(学習利用の有無)を確認して選定する(→ 13章)
- AI出力に含まれる外部コード・コマンドは、理解してから実行する

## 事故対応(発生時の順番)

```
1. 拡大を止める(キー無効化・公開停止)
2. 影響範囲の特定(何が・いつから・誰に)
3. 関係者への正直な報告(クライアント含む。隠蔽は事故より重い)
4. 復旧 → 5. ポストモーテム(犯人探しではなく構造の修正)→ 再発防止を仕組みに落とす
```

## 基本衛生

- 主要アカウントは2要素認証+パスワードマネージャー
- バックアップは「復元テストをして初めてバックアップ」/ 本番作業の前にバックアップ
