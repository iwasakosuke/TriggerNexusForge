# 06 開発

## 開発の原則

1. **設計より先に動くもの** — 完璧な設計書より、動く最小構成(MVP)。Core Engine の前例に従う
2. **動作検証なしに「完成」と言わない** — 実際に実行・操作して確認(可能ならヘッドレスブラウザ等で自動検証)
3. **依存は最小に** — 追加する部品(ライブラリ・サービス)1つごとに保守が増える
4. **インターフェースを固めてから中身を作る** — 入出力契約が固まっていれば中身は差し替え可能

## 標準の開発フロー

```
1. 要件:機能一覧+受け入れ基準(◯◯すれば合格)を先に書く
2. 最小実装:1機能ずつ動かす(全部作ってから動かすの禁止)
3. 検証:受け入れ基準を実際に実行して確認。証拠(ログ・スクショ)を残す
4. 記録:README(起動方法・構成・技術選定の理由)を書いてからコミット
5. リリース:07_RELEASES に記録
```

## 技術選定の判断基準

- 一人で運用できるか(運用コスト>開発コスト)
- AIコーディング支援と相性が良いか(メジャーなエコシステム)
- 撤退しやすいか(ロックインの弱さ、データのエクスポート性)
