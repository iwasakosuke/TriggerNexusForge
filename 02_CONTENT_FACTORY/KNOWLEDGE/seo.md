# SEO — 検索最適化の基準

<!-- Blog記事の設計・検品に使うSEO基準。「検索エンジンではなく、検索した人に書く」が大原則 -->

## 大原則

> **順位を上げるテクニックより、検索意図への最適解。**
> Googleの評価軸(E-E-A-T)は「読者にとって最良か」の代理指標にすぎない。

## 1. キーワードと検索意図

- **1記事1キーワード** — 欲張ると全部で順位が付かない
- 検索意図を3分類で分解する:
  - **Know**(知りたい): 定義・仕組み・比較 → 網羅と分かりやすさで勝つ
  - **Do**(やりたい): 手順・方法 → 再現できる具体度で勝つ
  - **Buy**(選びたい): 比較・レビュー → 一次体験と誠実さで勝つ
- 書く前に上位10記事を確認し、「共通して答えていること(必須)」と「誰も書いていないこと(差別化)」を分ける

## 2. E-E-A-T(TNFの勝ち筋は Experience)

| 要素 | TNFでの実装 |
|------|------------|
| **Experience(経験)** | 一次体験を必ず入れる(スクショ・数字・失敗談)。**ここが最大の差別化** |
| Expertise(専門性) | 実務者としての具体的な手順・判断基準を書く |
| Authoritativeness(権威性) | 実績の蓄積・プロフィールの整備で長期的に構築 |
| Trust(信頼性) | 誇大表現ゼロ・出典明記・更新日の明示 |

## 3. タイトル・メタ情報の基準

| 項目 | 基準 |
|------|------|
| タイトル | 32字以内/キーワードは前方/数字・具体性を入れる/釣らない |
| メタディスクリプション | 120字以内/検索意図への答えの要約+読む理由 |
| URLスラッグ | 英語小文字ケバブケース(`ai-lp-production`) |
| 見出し(H2/H3) | キーワードの自然な含有/見出しだけで記事の流れが分かる |

## 4. 記事構成の基準

- リード文(冒頭)で検索意図への答えを出す — 「結論ファースト」はSEOでも正義
- H2は3〜6個。1つのH2に詰め込みすぎたらH3に分割
- 手順は番号付きリスト、比較は表 — 構造化はリッチリザルトにも効く
- 画像には内容を説明する alt を付ける

## 5. 内部リンク

- 新記事公開時に必ず2方向を設計する:
  - 新記事 → 既存記事(関連する深掘りへ)
  - 既存記事 → 新記事(**既存記事の更新を忘れない**)
- アンカーテキストは「こちら」ではなくリンク先の内容が分かる語にする

## 6. 公開後の運用

| 時期 | やること |
|------|---------|
| 1ヶ月 | Search Console で表示回数・掲載順位を記録 |
| 3ヶ月 | リライト判断(順位11〜30位の記事が最優先=伸びしろ最大) |
| 6ヶ月〜 | 情報の鮮度確認(古い数字・仕様変更の更新) |
