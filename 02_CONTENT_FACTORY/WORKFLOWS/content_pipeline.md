# Content Pipeline — メイン生産工程

<!-- 1テーマ→多媒体展開の詳細手順書。この工程どおりに動けば、迷わず6媒体分が生産できる -->

## 全体フロー

```
┌─────────── STEP 1: 入力(30分)───────────┐
│ テーマブリーフ作成(theme_brief.md)         │
│ 担当:オーナー+SNS_AI                      │
└──────────────────┬───────────────────────┘
                   ▼
┌─────────── STEP 2: 生成(AI並行)──────────┐
│ 軸コンテンツ生成 → 派生コンテンツ生成        │
│ 担当:Copywriter_AI / SNS_AI / Designer_AI │
└──────────────────┬───────────────────────┘
                   ▼
┌─────────── STEP 3: レビュー(人間直列)─────┐
│ AI検品 → オーナー最終承認                   │
│ 担当:各AI(Rules.md)→ オーナー            │
└──────────────────┬───────────────────────┘
                   ▼
┌─────────── STEP 4: 出力─────────────────┐
│ OUTPUTSに保存 → 公開 → 数字の記録          │
│ 担当:オーナー(公開)+ SNS_AI(記録)      │
└──────────────────────────────────────────┘
```

---

## STEP 1: 入力 — テーマブリーフの作成

**ゴール: 「何を・誰に・どの媒体で」を1枚に固めてから工場を動かす**

1. ネタ候補から今週のテーマを1つ選ぶ(基準:一次体験があるか>ウケそうか)
2. `theme_brief.md` をコピーして記入する(テーマID発番:`T-YYYYMMDD-連番`)
3. 展開する媒体を決める(全媒体が義務ではない。テーマと媒体の相性で選ぶ)

**媒体選定の目安**:

| テーマの性質 | 軸コンテンツ | 派生 |
|-------------|------------|------|
| ノウハウ・手順(再現性がある) | Blog(SEO)or note | X スレッド+Instagram カルーセル |
| 体験談・失敗談(物語性がある) | note | Threads 連投+X 単発 |
| 気づき・考え方(軽い) | X 単発 or Threads | 反応が良ければ note に昇格 |
| 商品・サービス(売るものがある) | LP | 全媒体から導線を張る |

## STEP 2: 生成 — AI並行生成

**ゴール: 1つのブリーフから媒体別ドラフトを同時に作る**

1. **軸コンテンツを先に生成する**(長文が先。派生は軸から切り出す)
   - Copywriter_AI を起動し、ブリーフ+`PROMPTS/`(Blog.md / note.md / LP.md)で生成
   - 長文は「構成案→オーナー承認→本文」の2段階を守る
2. **派生コンテンツを並行生成する**
   - SNS_AI を起動し、`PROMPTS/X.md` の「多展開プロンプト」に軸コンテンツを投入
   - X 単発×3/スレッド×1/Threads×2/Instagram 構成×1 を一括生成
3. **ビジュアルを発注する**
   - 図解・カルーセルは Designer_AI へ設計指示(SNS_AI が指示書を書く)
4. 生成物はすべて `TEMPLATES/` の該当テンプレートに流し込む(メタ情報を記入)

## STEP 3: レビュー — 検品と承認

**ゴール: 「公開してよい品質」だけを通す。ここが品質の門番**

1. **AI検品(一次チェック)** — 生成した本人ではないAIが検品する
   - 言葉:Copywriter_AI が `KNOWLEDGE/writing_rules.md` + `brand_tone.md` で検品
   - SEO:Blog記事は `KNOWLEDGE/seo.md` のチェック項目を通す
   - ビジュアル:Designer_AI が Brand 適合を確認
2. **事実確認** — 数字・体験談・実績がすべて事実か(【要確認】タグの解消)
3. **オーナー最終承認** — 差し戻しは理由付きで STEP 2 へ。承認したら状態を `approved` に更新

**差し戻し基準(1つでも該当なら差し戻し)**:
- NGワードがある/事実未確認の数字がある/一次体験がない
- 軸とズレている(ブリーフの「読者のゴール」に貢献しない)

## STEP 4: 出力 — 保存・公開・記録

**ゴール: 公開して終わりにしない。資産化と学習まで**

1. 承認済みコンテンツを `OUTPUTS/` に保存する(命名規則は `OUTPUTS/README.md`)
2. オーナーが公開する(**公開ボタンは人間**)。公開日時を記録
3. 公開から48時間後・1週間後の数字を記録する(SNS_AI)
4. 反応が良かったものは:
   - `PROMPTS/` の出力例ストックに追記(生成の改善)
   - 別媒体への再展開を検討(note昇格・図解化など)

## スケジュールの目安(週1テーマ運用)

| 曜日 | 工程 |
|------|------|
| 金 | STEP 1: 来週のテーマブリーフ作成 |
| 月 | STEP 2: 軸コンテンツ生成(構成→承認→本文) |
| 火 | STEP 2: 派生生成+図解発注 / STEP 3: AI検品 |
| 水 | STEP 3: オーナー最終承認 |
| 木〜 | STEP 4: 順次公開(媒体ごとに時間差で) |

※進行が崩れたら PM_AI に相談(工程の組み替え・削る媒体の判断)

## 例外処理

- **時事性の高いネタ**: ブリーフを簡易版(テーマ・読者・ゴールの3行)にして即日生産可。ただしレビュー(STEP 3)は省略しない
- **クライアント案件のコンテンツ**: この工程に加えて、クライアントのレギュレーション確認を STEP 3 に追加する
