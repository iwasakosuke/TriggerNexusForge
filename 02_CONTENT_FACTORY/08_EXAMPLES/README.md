# 08_EXAMPLES — 実例集(勝ちパターンの記録)

<!-- 「売れた・伸びた」コンテンツの記録庫。工場の勝率を上げる最重要資産 -->

成果が出たコンテンツ(S級)を**再現可能な形で**記録します。
数字の自慢帳ではなく、「なぜ効いたか」を分解して次に使うための資産です。

## ファイル一覧

| ファイル | 記録対象 | 成果の定義(記録基準) |
|---------|---------|---------------------|
| [note_wins.md](note_wins.md) | 売れた・読まれたnote | 有料販売◯部以上 / スキ率が平均の2倍 |
| [lp_wins.md](lp_wins.md) | 成約したLP | CV発生 / CVR 2%以上 |
| [threads_wins.md](threads_wins.md) | 伸びたThreads | リプライ率・表示が平均の3倍 |
| [instagram_wins.md](instagram_wins.md) | 伸びたInstagram | 保存率が平均の2倍 / フォロワー外リーチ50%超 |
| [ads_wins.md](ads_wins.md) | 効いた広告・セールス文 | CPA目標内 / 反応率が平均超え |

※基準値は実績が溜まったら実数で更新する(最初は「自己ベスト更新」を基準にしてよい)

## 記録フォーマット(全ファイル共通)

```markdown
## (日付)タイトル・投稿の1行目

### 数字
(何がどれだけ。比較対象も:平均◯に対して◯)

### 現物
(本文の全文 or OUTPUTSへのリンク)

### なぜ効いたか(分解)
- フック:
- 構成:
- タイミング・文脈:

### 再現レシピ(次に使う形)
(「◯◯の場面では◯◯の型を使う」の1〜2行)

### 反映先
- [ ] 02_PROMPTS/◯◯.md の出力例ストックに追記した
```

## 運用ルール

- **S級判定(→ `00_RULES/quality_standards.md`)が出たら72時間以内に記録する**(記憶が新しいうちに分解する)
- 「なぜ効いたか」は仮説でよい。ただし仮説と事実を区別して書く
- 四半期ごとに見返し、共通パターンを `06_KNOWLEDGE/` や `02_PROMPTS/` に昇格させる
- クライアント案件の実例は、掲載許可の範囲でのみ記録する
