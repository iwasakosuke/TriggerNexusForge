# 05_OUTPUTS — 出力倉庫(業種別)

<!-- 完成コンテンツの保存場所。リポジトリが原本、公開先(note・X等)はコピー -->

生産したコンテンツの**業種別保存場所**です。ここが原本、各プラットフォームはコピーという位置づけで管理します。

## フォルダ構造(業種 → テーマの2階層)

```
05_OUTPUTS/
├── ai_company/     # AI会社(自社発信)
├── beauty/         # 美容
├── restaurant/     # 飲食
├── professional/   # 士業
├── seitai/         # 整体
├── web_production/ # Web制作
├── salon/          # サロン
├── recruiting/     # 採用
└── (業種)/
    └── T-YYYYMMDD-01_短い名前/   # テーマフォルダ
        ├── _input.md             # 入力シート(01_INPUT のコピー)
        ├── blog.md               # 軸コンテンツ(03_TEMPLATES 形式)
        ├── x_thread.md           # 派生コンテンツ
        ├── line.md / mailmag.md  # 配信系
        └── images/               # 図解・画像・生成プロンプト
```

## 命名規則

| 対象 | 規則 | 例 |
|------|------|-----|
| 業種フォルダ | 小文字スネークケース(英語) | `web_production/` |
| テーマフォルダ | `テーマID_短い名前` | `T-20260710-01_lp-jidouka/` |
| コンテンツファイル | `媒体_形式.md`(小文字) | `x_thread.md` `instagram.md` |
| 画像 | `媒体_連番.png` | `instagram_01.png` |

## 状態管理

各ファイル冒頭のメタ情報(`状態:`)で管理:

```
draft(生成直後)→ review(検品中)→ approved(承認済)→ published(公開済)
```

- 状態を飛ばさない(検品スキップ禁止)
- `published` 時に公開URL・日時を記入、公開後の数字(48時間・1週間)も追記する

## 運用ルール

- **公開前にコミット** — 公開したのにリポジトリにない状態を作らない
- **ボツ案も消さない** — 没ドラフトは学習材料(末尾に「没理由」を1行)
- **四半期で棚卸し** — 高反応コンテンツの再展開・リライト候補を洗い出し、S級は `08_EXAMPLES/` へ
- **新業種の追加** — 業種フォルダを追加し、`03_WEB_STUDIO/INDUSTRY_TEMPLATES/` に業種知見も追加する
