# OUTPUTS — 制作物倉庫

<!-- 完成コンテンツの保存場所。リポジトリが正、各プラットフォームはコピー -->

生産したコンテンツの保存場所です。**ここが原本、公開先(note・X等)はコピー**という位置づけで管理します。

## フォルダ構造(テーマ単位)

```
OUTPUTS/
└── T-YYYYMMDD-01_テーマの短い名前/
    ├── _brief.md        # テーマブリーフ(WORKFLOWS/theme_brief.md のコピー)
    ├── blog.md          # 軸コンテンツ(TEMPLATES/Blog.md 形式)
    ├── x_thread.md      # 派生(TEMPLATES/X.md 形式)
    ├── x_single.md
    ├── threads.md
    ├── instagram.md
    └── images/          # 図解・画像(Designer_AI 成果物)
```

## 命名規則

| 対象 | 規則 | 例 |
|------|------|-----|
| テーマフォルダ | `テーマID_短い名前` | `T-20260710-01_lp-jidouka/` |
| コンテンツファイル | `媒体_形式.md`(小文字) | `x_thread.md` `instagram.md` |
| 画像 | `媒体_連番.png` | `instagram_01.png` |

## 状態管理

各ファイルの冒頭メタ情報(`状態:`)で管理する:

```
draft(生成直後)→ review(検品中)→ approved(承認済)→ published(公開済)
```

- 状態を飛ばさない(draft から直接 published にしない)
- `published` になったら公開URL・公開日時をメタ情報に記入する
- 公開後の数字(48時間・1週間)も同ファイルに追記する(→ 各テンプレートの記録欄)

## 運用ルール

- **公開前にコミット** — 公開したのにリポジトリにない状態を作らない
- **ボツ案も消さない** — 没にしたドラフトは学習材料(ファイル末尾に「没理由」を1行)
- **四半期で棚卸し** — 反応が良かったコンテンツの再展開・リライト候補を洗い出す
