# GITHUB Knowledge

## TNFにとってのGit(なぜ使うか)

- 会社OSの**すべての変更履歴**が残る=「なぜ今の形か」を遡れる
- 壊しても戻せる=思い切った改善ができる
- AI(Claude Code)との共同作業の土台になる

## 基本概念(最小限)

| 概念 | 一言 |
|------|------|
| commit | 変更のセーブポイント(意味のある単位で切る) |
| branch | 並行世界。main を壊さずに作業する場所 |
| merge / PR | 並行世界を本流に合流させる(PRはレビューの場) |
| push / pull | リモート(GitHub)との同期 |

## TNFの運用ルール

- **main は常に「会社の現在の正」** — 壊れた状態でmainにしない
- 作業は機能単位のブランチで行い、まとまったら main へ
- コミットメッセージは「何を・なぜ」(例:`Add LP template for beauty salon projects`)
- 認証情報・クライアント機密は**絶対にコミットしない**(履歴からの完全削除は困難)
- 週1回は push する(ローカルだけの資産を作らない)

## コミット単位の考え方

- 1コミット=1つの意味(「LP追加+誤字修正+ルール変更」を混ぜない)
- 「なぜ」が書けないコミットは、単位が大きすぎるサイン
